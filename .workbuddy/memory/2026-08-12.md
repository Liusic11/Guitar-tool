## 空白页真因修复（puppeteer 诊断）✅
- 用户硬刷新仍空白 → 用 `puppeteer-core` + 系统 Chrome 实测：进和弦页→点切换训练，捕获到 `PAGEERROR: Rendered fewer hooks than expected`（来自 `<ChordLibrary>`）。
- **真正根因（非旧 bundle）**：`ChordLibrary` 里有 `if (mode === 'changes') return <ChordChanges/>` 的 **early return 位于多个 useMemo 之前**。参考模式渲染 13 个 hook、切换训练模式只渲染 7 个 → 切模式时 hook 数量不一致 → React 整页（含顶栏）白屏。
- **修复**：删掉 early return，改为在 `return` 处用三元分支 `mode === 'changes' ? <ChordChanges/> : <main>…参考…</main>`，组件内全部 hook（6 useState + 1 useEffect + 6 useMemo）无条件调用，两模式 hook 数一致。
- 实测复验：切换训练页 `header/main 均 present、mainLen 606、含「计时换把」`，无 hooks 报错；仅剩无害的 favicon 404。

## 节奏系统重做 + 音阶练习模式简化（用户 2026-08-12 反馈）✅
用户主张：跟弹/跟拍本质一样，练琴时难腾手反复点页面 → 去掉跟弹；模进也要跟拍自动走；演示要边播边高亮每个音；节拍要更多选型（4/4、三连音、架子鼓如动次打次）；节奏控制移到设置里、置于「音色」段下方。

### 改动
- **删 `跟弹`(sequence) 模式**：`ScaleTrainer` 的 Mode 现为 `map|follow|pattern|ear`。`跟拍`(follow) 即原升序跟拍走法；`模进`(pattern) 改为**跟拍驱动**——`activeRouteRef` 含 `patternRun`，底 bar 每拍自动推进（手动点只试听），与 follow 共用同一套 done/answer/ghost 高亮。
- **演示高亮**：`playDemo` 重写成边播边驱动 `demoActive/demoIdx`；`highlights` 加「演示优先」分支，`demoRoute` = 升序+下行（pattern 模式用 patternRun），指板与把位形状卡同步点亮每个音（done/answer/ghost）。演示期间 `advanceFollow` 早退，避免跟拍指针漂移。
- **节奏模型重做**（`src/lib/rhythm.ts`）：移除旧 `GROOVES/stepLabel`，改为 `RHYTHM_PRESETS`——6 个预设：`4/4 节拍器 / 8分 节拍器 / 4/4 动次打次(架子鼓) / 三连音 节拍器 / 三连音 架子鼓 / Funk 16分(架子鼓)`。每预设含 `kit(click|drums)`、`subdiv`(每拍步数)、`steps`(一小节 kick/snare/hat/accent/tick)。全部 4 拍/小节，onBeat 每拍回调一次。
- **共享节奏状态**（`src/lib/rhythmStore.ts`）：`useSyncExternalStore + localStorage` 存 `bpm/presetId`，设置抽屉写、RhythmBar 读，跨模块一致。
- **鼓组合成**（`audio.ts`）：新增 `kick()/snare()/hat()`（连 master，不经琴体链），供架子鼓预设。
- **RhythmBar 精简**：移除底部 groove 选择 chips，只留 播放/停止 + 鼓点/拍点可视化条（读 store 的 bpm/preset）；调度器按 preset.subdiv/steps 播放 click 或鼓组。
- **设置抽屉**：「音色」段下方新增「节奏」段（BPM 40–200 滑块 + 节拍型 chips，来自 RHYTHM_PRESETS）。
- **RhythmTrainer**（原死代码，App 未渲染）改写以兼容新模型 + 读 store，作为 #40 节奏律动页的雏形，避免编译断裂。
- 右侧乐理文案「跟弹」→「跟拍」。
